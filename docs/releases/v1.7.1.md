## 1.7.1

**缺陷收口版本。** 不动功能面，只修「上游交互、错误码与本地数据」这三处一直不真实的地方：回合结束时释放队列租约的请求一直在白打 500，用户填错 PAT 会被报成服务器错误，清空用量没有任何回滚余地。

### 修复

- **每轮对话都白打一次 500**：`/algo/api/v2/service/ask/finish?Encode=1` 要求请求体本身是 Qoder 自定义 Base64（`qoderEncode`），插件从 1.6 起一直发明文 JSON。实测日志里有 633 条「释放 Qoder 租约失败 HTTP 500」，等于每次回复结束都多打一次必败请求；上游只能等 TTL 回收队列租约，同账号下一条提示可能排在上一条后面。现在签名和请求体都用编码后的字节，真实网关实测由 500 变 200。
- **填错 PAT 被报成服务器错误**：空 PAT、不认识的前缀、本机找不到可导入账号、令牌验证失败，抛的都是没有 `statusCode` 的裸 `Error`，路由只能按 500 回，面板统一显示「远程服务器返回 500（内部服务器错误）」。现在按语义返回 400 / 401 / 404 / 502，并带上可直接读懂的原因。
- **4xx 污染失败日志**：面板路由把所有异常都记成 `panel route failed`，日志里堆的是「请输入 PAT」「auto 必须是布尔值」这类用户操作，真正的 5xx 反而被淹没。现在只有 5xx 记。
- **清空用量不可回滚**：原来直接删 `usage.json` 与 `usage.daily.json`。现在先改名成 `usage.json.bak-<时间戳>`，面板提示里会写出备份文件名。
- **日志里只有 `[object Object]`**：`redact()` 对对象做 `String()`，614 条「消息序列已清洗」完全看不出裁剪了几张图、多少字节。现在对 Error / 对象做安全序列化，单行超长才截断。
- **成功请求被算成「需处理」**：`errorAction(undefined)` 返回 `fail`，成功记录也带上了 `errorAction: 'fail'`（实测 97 条成功记录里 6 条），概览的失败动作分布和「仅需处理」筛选都跟着失真。
- **面板日志页重启后空白**：内存环形缓冲只覆盖本进程启动之后。现在从 `qoder.log` 尾部按需读回（只读最后一小段），读不到才用内存缓冲。
- **额度可能显示 `NaN`**：`Number('abc')` / `Number('1,200')` 不再被当成有效数字，缺失就如实标「剩余未知」。

### 已知边界

- 备份文件不会自动清理；需要腾空间时手动删 `~/.dsh/qoder/usage.json.bak-*`。
- 释放租约仍是 best-effort：网关故障时只写日志，不影响已经完成的回复（`QODER_ASK_FINISH=0` 可整体关闭）。
- 面板日志页展示文件尾部的原始行（含重启前的历史），但环形缓冲上限仍是最近 200 行。

### 升级

tgz（推荐，可核对 SHA-256）：

```bash
dsh plugin --profile desktop add ./qoder-to-dsh-1.7.1.tgz
```

GitHub 直装：

```bash
dsh plugin --profile desktop add github:Ianzhyh/qoder-to-dsh
```

装完**完全退出 dsh 再打开**。如果面板顶部提示“已加载 vX，磁盘 vY”，说明还在跑旧代码。

- 凭据、偏好、用量、签到与目录缓存都在 `<DSH_HOME>/qoder`，升级不会清空。
- 从 1.7.1 回滚到 1.7.0 时，多出来的 `.bak-*` 文件会被旧版本忽略，不影响读取。
- 已经登录的账号不需要重新授权。
